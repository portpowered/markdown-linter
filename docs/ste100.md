# Simplified Technical English checks

The vocabulary and grammar checks provide configurable lexical guidance.
They require a reviewed vocabulary and do not certify full STE100 compliance.
Editors still review meaning and part of speech.

## Activation

Keep approved forms inside the version 2 configuration.
No dictionary file is read.

```yaml
version: 2
rules:
  approved:
    check: text.ste100.dictionary
    options:
      dictionary: [to, will, the, use, do, a, give, gives, gave, given]
      technical-terms: [query shape]
  grammar:
    check: text.ste100.grammar
    options:
      max-sentence-words: 25
      forbidden-patterns:
        contractions: "(?i)\\b[a-z]+['’](?:t|s|re|ve|ll|d|m)\\b"
sets:
  technical:
    use: ["markdown:recommended"]
    rules:
      - {rule: approved, on: document}
      - {rule: grammar, on: document}
apply:
  - use: [technical]
```

Run `marklint --config .marklint.yaml docs`.
The [example policy](../examples/ste100/.marklint.yaml) shows a small approved vocabulary.

## Vocabulary behavior

Dictionary words are approved surface forms, compared without case sensitivity.
Listing a base word does not approve other forms.
Add each approved inflection deliberately.
Technical terms approve complete phrases without approving their words elsewhere.
Matching permits emphasis and soft line breaks within a paragraph.
Punctuation, code, images, and paragraph boundaries stop phrase matching.

Prose includes paragraphs and headings by default.
Use the check option `scope: heading` to restrict its text selection.
Code, URLs, frontmatter, and HTML syntax are excluded.
Link labels remain prose.

## Grammar behavior

The sentence limit counts lexical words within paragraph and heading text.
Named forbidden patterns use Go RE2 syntax.
Names appear in findings, and invalid expressions fail configuration validation.
Patterns identify finite constructions and require editorial review.

Use `core.limit` for Unicode sentence budgets across supported formats.
The STE adapter retains its historical lexical counting behavior.
The [single-file guide](single-file-policy.md) explains that distinction.

## Tests and maintenance

Review vocabulary changes like code changes.
Confirm every approved form against your writing standard.
Test accepted examples and near misses.
CI checks the project documentation using its committed inline vocabulary.
Race tests and the 95% coverage gate check the implementation.
